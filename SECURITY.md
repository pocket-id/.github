# Security Policy

## Supported Versions

Use the latest stable release of each Pocket ID project. Security updates are provided for the latest release. Read the release notes before upgrading between major versions.

## Reporting a Vulnerability

Thank you for taking the time to report a vulnerability. Please do not report vulnerabilities in public GitHub issues.

Open the affected repository's **Security and quality** tab and use **Report a vulnerability** to report it privately. If private reporting is unavailable there, report it through [Pocket ID's private vulnerability reporting form](https://github.com/pocket-id/pocket-id/security/advisories/new), specifying the affected repository.

See the [GitHub documentation on privately reporting a vulnerability](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately) for details.

## AI-Assisted Reports

We aren't against AI, we use it a lot ourselves. But we receive dozens of reports every week, most of them AI-generated false positives, and it's impossible to review them all in detail.

Running an AI tool over our codebase rarely turns up anything new. We have access to the same flagship models, including advanced ones like Mythos and Daybreak, and scan our repositories with them regularly. A report that only passes on what an AI tool found therefore adds little.

If you use AI tools anyway, please follow these guidelines:

1. You must be able to explain the issue, its impact and its preconditions in your own words.
2. Write the report and your comments yourself instead of pasting AI-generated text. We know it's much easier to let AI write it, but a report in your own words is our first sign that you genuinely understand it.

Reports that appear to be purely AI-generated may be closed without a detailed explanation of why they were not accepted as a vulnerability.
